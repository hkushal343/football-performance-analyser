# Demonstration script (about 6 minutes)

1. **Introduce (30 s).** "This app analyses football matches. It uses Python, Streamlit, Pandas and Plotly. The data is a synthetic sample CSV, and I can swap in real data later."
2. **Dashboard (1 min).** Point at the five cards. Say each number is calculated from the CSV. Open the four chart tabs and hover over a bar to show the tooltip.
3. **Sidebar filters (45 s).** Untick *Challenge Cup* and *Friendly Series*, narrow the dates, watch every page update. Press **Clear all filters**.
4. **Match Explorer (1 min).** Search "Northbridge", choose *Draw* in Result, then download the CSV and open it.
5. **Team Comparison (1 min).** Pick two teams. Show cards, the side-by-side table, the two charts and head-to-head matches.
6. **League Standings (1 min).** Choose only *Premier Division*. Explain 3/1/0 points and the sort order. Mention the tie-break limitation shown in the expander.
7. **Data and Downloads (45 s).** Show the data quality check and the three downloads.
8. **Code tour (1 min).** `data_loader.py` cleans, `analytics.py` calculates, `charts.py` draws, `app.py` shows. Run `python -m unittest discover -s tests -v` to show 37 passing tests.
9. **Close.** Show the public link and mention future improvements.

# Likely viva questions and simple answers

**1. What does the project do?** It loads football match data, calculates team statistics and standings, and shows them in an interactive web dashboard.

**2. Why Streamlit?** It lets me build a web interface in Python without HTML, CSS or JavaScript, and it deploys free on Streamlit Community Cloud.

**3. Why Pandas?** It is made for tables. Filtering, grouping and summing thousands of rows takes a few lines.

**4. Why is the data separated from the code?** The CSV is replaceable. As long as the columns match, the app works with a different dataset.

**5. Is the data real?** No. It is synthetic: fictional teams and random scores generated by `scripts/generate_sample_data.py` with a fixed seed.

**6. How does data move through the app?** CSV → `load_matches` (validate and clean) → filters → `analytics` functions → tables, charts and downloads.

**7. How are wins, draws and losses calculated?** I turn each match into two team rows. If goals for are higher than goals against it is a win, equal is a draw, lower is a loss.

**8. How are points calculated?** Win = 3, draw = 1, loss = 0, summed per team.

**9. How are standings sorted?** Points first, then goal difference, then goals scored. Team name is used last only to keep the order stable. Head-to-head rules are not implemented because the data does not support them.

**10. What is goal difference?** Goals scored minus goals conceded.

**11. How do you avoid division by zero?** Win percentage and goals per match use a safe divide that returns 0 when there are no matches.

**12. What validation do you do?** I check required columns, convert dates and scores, and remove rows with invalid dates, missing or negative or non-whole scores, blank names, same-team matches and duplicate IDs. The removed rows are counted and shown to the user.

**13. What happens with an empty dataset or empty filters?** The app shows a friendly message and the charts return an empty figure instead of crashing.

**14. What is `st.cache_data`?** It stores the loaded data so the CSV is not re-read on every click. It refreshes when the file changes.

**15. How do the downloads work?** The same table shown on screen is converted with `to_csv`, and `st.download_button` offers it as a file.

**16. How did you test it?** Unit tests with a tiny hand-calculated dataset check statistics, standings, filters and validation. I also follow a manual checklist for the screens.

**17. What are the limitations?** Synthetic data, no live scores, simple tie-break rules, no knockout-cup modelling.

**18. How would you improve it?** Upload a real dataset in the app, season selector, form guide, player statistics, logos.

**19. How is it deployed?** The code is pushed to GitHub and Streamlit Community Cloud builds it from `requirements.txt` and runs `app.py`.

**20. Which parts did AI help with and what do you understand?** AI helped draft the code. I can explain every file: loading and cleaning, the two-rows-per-match idea, grouping for statistics, sorting for standings, and charts.
